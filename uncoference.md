# Session 1: Build the System, not the code - Danny Warren
- Treat AI as a new Junior Dev that is still learning your system. It might take AI a while to learn your system, it will take time before you can trust it. 
- Have agent write the tests, then have a different one implement the code
- Vertical slice architecture?


# Session 2: Preserving/Capturing Engineering Judgement in the age of AI Daniel Scheufler
- When learning with AI ask it to grill it so that you are forced to explain your own understanding of different concepts. 
- Iterative improvement, write down what you learn so that you can use it next time.
- When you gety to an end result ask the agent what was missing from my original prompt, how could we get there faster next time.
- Don't have AI write your skills


# Session 3: How to improve/maximize our internships - Chase Harmer
- Open Seseame - Mark Munson says they offer internships every summer
- Drink from the firehose and ask a lot of questions
- The point of mobbing and pair programming is to get a lot of different perspectives, if your ideas aren't welcome you should find a different place to intern
- Nobody really knows what they are doing with AI and what they are doing right now
- You should do side projects
- It is good to be uncomfortable, that is where learning occurs
- Skills you learn from SE are good skills regardless of where you end up working
- Taste is what is impotant, you need something to help set your product apart when anyone can use claude to build their own
- The field is changing all of the time, you need to be willing to adapt
- Take time to figure out what LLM's are good for, experiment with them
- You need to be able to work with other people
- More of the job with consist of talking to the customer and communication
- People will usually come to you with your solution not the problem
- Get to know people even people in other departments
- Show how to show how you can be an asset to the company
- Speak with confidence, if you don't have confidence in a specific thing, speak with confidence that you are learning more about that thing



# Session 4: AI Retro - Ellis Lempriere
- Anyone can produce code, but not everyone can produce quality code
- Learn about XP
- Pilots are still required stick time, even with autopilot, it should be the same with coding
- We learn from stuggling
- You never stop learning, take time to learn


# Session 5: Intro to Software Teaming and Q&A - Woody Zuill
- Mob programming means working on the same thing, at the same time, on the same computer. 
- Mob programming gives you a fast feedback loop, you don't have to wait to hear concerns or questions
- Driver and Navigatores, the navigators tell the driver what to do
- "For an idea to go from someone's head into the computer it must go through someone else's hands." - Llewellyn Falco
- Optimize for the flow of the work rather than the output of the individual 
- Get the best of each member into the work
- The people doing the worst are the best suited to manage that work
- Personal performance reviews aren't condusive to teamwork
- It takes time to get this right
